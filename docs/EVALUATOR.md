# 自由角色台词评分器：数据、接口与校准

> v0.2 · 2026-11-01。当前只有[类型接口与组合器](../data_factory/scoring.py)，**没有已训练权重，也没有毫秒级吞吐结果**。数据Agent现在就应生产其监督数据，不等GPU训练完成。

## 1. 从自然文本到奖励的完整接口

策略自由生成台词，不能要求它自己输出一个“我做对了”的评分JSON。独立评分器读取：自然人设／必要历史、当前可见条件、当前适用契约、候选回复。得到：

- `decision`：自然回复实际表达的决定；原始提取可用自然语言，再映射到族内decision_inventory。条件性合作、含混、核实等不能硬塞成二元接受／拒绝。
- `decision_ok`：该决定是否在当前允许集合内。
- `grounded`：所用依据与可见输入是否相容，有没有伪造许可／亲历／核验结果。
- `naturalness`：相关、自然、人物可信且不过度表演；平实回复可以高分。
- `requested_conditions`、`feasible_verification`、`premature_commitment`：B6核验的独立读出。
- `confidence`与`status`：成功、弃权、解析错误、服务错误必须区分。

组合器计算q=decision_ok×grounded×verification_ok，自然度只在q内部参与节点奖励。分支类别、作者标签不能作为actor输入，但允许评分器使用经过审查的当前节点rubric。评分器不需要兄弟分支、未来事件或人物不可见的世界真相。

长历史不能随便截成一个失去决定依据的摘要。先用完整输入标注，再验证压缩的决定相关视图；若使用摘要，保存证据原文指针并评估遗漏率。抽取器将文本误读为已核验时，后续规则计算并不能修复，因此该切片必须单独校准。

## 2. 四格数据如何变成训练数据

2,000族×12节点×4候选最多产生96,000个基础候选实例；它们是候选监督资源，不是自动拥有精确多维标签的金标。

`intended`保存生成任务要求，`observed`保存独立盲审与仲裁的实际结果。四格直接控制的是决定意图与表达方式，不能因此推断证据正确性、自然度和核验质量已被独立标注。

候选盲审员先只看actor输入和候选正文，不看格子、chosen/rejected、预期决定或其他候选。输出实际决定、依据原文片段、缺失条件、是否伪造、自然度理由。之后仲裁器映射标签并处理歧义。审查失败保留原始文本和原因，不覆盖成作者期待的标签。

必须补充以下切片：决定正确但理由伪造；决定错误但忠实复述事实；自然的模糊拖延；提问与缺失条件不相关；尚未核验却直接承诺；自然克制与夸张表演的同决定对照。额外切片单独计数，不强行挤进原始四格。

## 3. 模型路线与训练目标

先使用已可部署的小型本地语言模型作为多头评分器候选，例如合适的1–4B级模型；多语编码器也可以试，但需实际验证中文和长上下文适配。不要因为名字叫DeBERTa就默认其中文／上下文能力满足需求。

实现可选两种：共享backbone加分类／回归头；或先用本地小模型输出短结构化评价，再蒸馏成多头模型。它们是可替换工程路线，不要求数据生产Agent现在先完成模型训练。

损失包含决定分类、决定合格度、依据合格度、B6语义槽位／可行性与自然度回归或排序。缺失／有歧义的标签使用mask或软标签，不自动填0。使用风格匹配对控制正确性判断，用同样正确的候选比较自然度。不要将多个主观维度挤成一个从头到尾不可解释的角色总分。

只用train及允许的pilot进行训练，在这些组内部留出评分器校准分区；dev用于选择，test完全不接触。相同人物／骨架的候选不能随机跨评分器训练与验证。关联于训练侧的学生实际rollout需增量标注，防止评分器只识别教师写得很整齐的负例。

## 4. B6语义与组合规则

`verification_routes=[[a],[b,c]]`表示请求a，或同时核实b和c，都是足以推进决定的路线。提取器从自然话映射requested_conditions，必须有原文支持；不能因为rubric里列了a，就替回复补上a。

v=1需要覆盖至少一条路线、核验动作可执行且没有提前承诺；模糊“我得核实”没有条件点名，v=0。允许同义表达和简短回复。程序规则在语义提取之后执行，不通过关键词计数直接判忠实。

## 5. 上线前的校准与运行监控

初始校准重点：决定混淆矩阵、证据误通过、hard-negative误通过、B6空泛／伪核验误通过、自然度偏好与人工抽样的一致性、弃权率。按人物动机、历史、分支、表达方式和长度分桶，不能只报总准确率。记录Brier/ECE等校准读出，但不把低ECE当语义正确的替代。

高置信批量由快评分器处理，低置信／分歧样本送较强离线裁判或审查队列。抽取一部分高置信样本随机审查，防止快评分器自信地系统性偏误。固定路由条件并保存覆盖率；不同方法不能获得隐蔽地不同的评分预算。

评分缓存键包含prompt与候选、rubric和评分器版本。超时、空输出、解析失败、无效ID不计为q=0，应重试／隔离并报告有效评分覆盖率。每轮更新冻结评分器；重训后用新版本写缓存，不污染旧结果。

实测p50/p95评分延迟、batch吞吐、prefill token量、峰值显存和端到端step占比。48条候选一次批量评分是否快取决于输入长度、模型与服务，不在文档里预填“几毫秒”或“慢十倍”。

## 6. 与RL及最终评价的隔离

训练评分器不是最终唯一裁判。独立冻结的评价协议／更强审查者和分层人工样本共同检验决定、依据、自然度。所有方法在相同协议下比较；旧论文不同judge的分数不直接拼榜。

强化学习收益先检查真实台词，再看分数。如果策略学会含糊表达来回避决定提取，或把核验句式当万能答案，作为评分器域移和新困难样本记录，而不是给模型加分。合理的不确定回答仍需保留，不能为了分类方便强迫二元决定。

## 7. 接口状态

`Evaluator.score_batch()`是待接真实backend的契约；`compose()`是可运行的标签组合与B6规则检查；`cache_key()`区分评分版本。它们不包含训练好的语义识别能力。训练脚本、checkpoint、校准报告和实际服务吞吐由本地GPU工作流另行产出，写入IMPLEMENTATION_STATUS与实验日志。
