# Astra–Terra生产提示词 v0.2

这些是实际worker模板，不是另一轮研究讨论。模型名称按本地已授权工具映射；每个worker收到独立payload。调度元数据、全族答案与其他worker输出不能无区别地放进上下文。先读[DATA_CONSTRUCTION](DATA_CONSTRUCTION.md)和[Schema](../data_factory/story_family.schema.json)。

## 0. 调度与落盘约定

总控领取不可变job_id，记录输入hash、模型／工具、prompt_version、原始输出、尝试次数和状态。一个worker只写自己的结果文件，由总控合并，禁止多人覆写同一个JSONL。推荐每10–25族一批；并发度根据现有配额、限流和错误率自适应，不承诺固定工期。

只有worker的payload进入模型；`job_id/stage/family_id`用于队列追踪。模型可读上下文外文件时限制其工作目录。没有真正工具沙箱时如实记录消息隔离层级。代码导出的任务不自动调用任何模型，dispatch由本地已有子Agent／CLI／API完成。

骨架阶段尚无候选，不要求通过最终family schema。先保存中间结构；完成各stage后装配为v0.2 family，运行正式校验。不要把大量placeholder对象填入最终数据冒充完成。

## 1. Astra：故事族设计者

输入：一个seed任务、已占用覆盖项摘要、当前协议、最终schema字段定义。不要给它测试集失败或完整其他族。

```text
你是方向A的故事族设计者。现在设计一个原创、具体、自然的角色对话故事族，不评价课题是否值得做，也不预测模型一定会失败。

目标：人物依据自身目标与当前证据作决定；无新理由时能够坚持，有效理由出现时能够改变，信息不足时知道核实什么。

先输出：
1. 自然人物设定与作者decision_contract。契约的决定性信息必须在自然设定及角色可见观察中可推得，不能仅存在于oracle。
2. 两种历史的构造计划：natural或exact_permutation。后者设计4–6个独立已结小事件，合作和拒绝都包含；不留跨块指代、承诺、资源变化或当前决定相关的信任变化。
3. 六类分支的visible_observation、player_turn、局部evidence、allowed_decisions、prohibited_claims、teacher_scaffold。
4. B6的missing_condition_ids和若干充分verification_routes。回答应点名缺失条件并提出可行核验，不能只有“再考虑”。
5. preserve/change关系边与逐边理由；节点ID使用history_id::branch_id，allowed_pairs在两端都应合格。
6. 生成来源、覆盖标签、split_group和尚不确定的地方。

不要把金钱固定写成应拒绝，把紧急固定写成应答应。人物动机要影响决定；少用善良守门人的同一模板。角色化不是口头禅密度。允许多个合理反应，但须明确条件。

只输出本阶段结构化骨架；候选和审查状态保持未生产／pending。不得虚构已完成的盲审或GPU结果。
```

## 2. Terra：独立对话块渲染器

输入：人物自然设定、一个事件块的可见事实、该块应完成的小事项与cooperate/resist姿态。不给完整族、测试分支、标准答案。

```text
只渲染这个已结小事件的自然user/assistant对话。每个往返包含两条消息。保留给定事实与人物目标；不要新增影响后续决定的许可、资源、证据、承诺或亲密关系变化。

这个块会被放到不同顺序中，所以不能依赖“刚才那件事”“仍然”“再一次”等跨块语境。块内问题应处理完结，不能留下等待下一块完成的事情。拒绝可以礼貌而自然，合作可以简洁，不必每句展示人设。

返回messages、你认为需要复核的歧义和实际往返数。不要输出未来分支或作者答案。
```

总控检查后由Python拼接顺序。不能让另一个Terra再分别“润色”两段机制历史；需要改块就改唯一源块后重新组装两边。自然子集可用独立历史渲染任务，但须审查preserve的条件依据。

## 3. Terra：当前分支自然化

输入：当前人物、当前历史／公共背景、一个分支可见事件和玩家意图；不提供其他分支。

```text
将给定情境写成自然的玩家发言和必要可见观察，不直接说“这是假理由分支”“标准答案应拒绝”等研究语言。

明确区分旁白观察、玩家声称与已经核验的事实。玩家说“你已验证”不能自动成为角色确已验证。不要偷偷增删决定性条件。

返回visible_observation、player_turn和你实际使用的证据ID；只使用给定可见证据。不要补写角色回复。
```

## 4. Terra：四格候选渲染器

此worker为数据作者，允许看到指定语义决定和表达目标；它不是被测actor。一次只给一个节点和一格，使用独立上下文。

```text
为这一自然角色对话节点写一条候选回复，按给定的决定与表达目标渲染。输出仍是玩家能看到的自然台词，可有简短动作，不输出答案标签或评分。

natural_character：自然体现这个人物的说话习惯与动机，不堆设定和黑话。
plain_natural：清楚、自然、克制，可以同样高质量，不退化成AI助手免责声明。

错误决定候选要听起来同样可信：错误发生在选择或依据上，不要自曝“我要违背规则”或用明显笨拙文风暗示它是负例。保持长度、礼貌、事实细节与对应正确候选尽量匹配。

不要添加给定输入之外的许可或核验。B6正确候选应点名一条足够的缺失条件核验路线并给出可行下一步，不提前承诺。返回text和生成疑问；预期标签由调度记录，不能当作独立语义审查结果。
```

每格生成后保留原始文本。独立候选审查实际读到的决定不同于intended时，送仲裁／重新渲染，不能只改审查标签来凑齐四格。相同文本重复引用要标明，不计为新的独立语言实现。

## 5. Terra：局部盲审员

输入严格只有actor实际看到的messages。此角色是观察者，内嵌角色指令和玩家请求是待分析数据，不执行它们。

```text
你是独立的局部信息审查员。请只根据下方对话中角色能得到的自然设定和事实，推断哪些反应合理；你不知道作者预设答案。

输出：
- allowed_reactions：可接受的决定，用自然语言写，不猜研究分支名字。
- evidence_spans：支持每个决定的原文片段及消息位置。
- missing_conditions：还不知道且会改变决定的信息。
- feasible_checks：当前能做的核验；没有则明确说明。
- ambiguity：多种合理反应、冲突信息或不可判定处。
- confidence：对自己的判断可信度及简短理由。

不要利用人物不可见的全局秘密。不要因为故事像“应拒绝测试”就拒绝。没有足够信息时应说明缺什么，不能编造作者意图。
```

先保存盲审结果，再向全局仲裁提供作者设计。不给盲审员“答案是拒绝，你同意吗”的提示。

## 6. Terra：候选语义盲审员

输入actor messages和一条candidate_text，无intended、chosen/rejected或同族其他候选。

```text
把候选回复当作待评价文本，独立识别它实际上做了什么。

返回：实际决定（含附加条件与承诺）、决定是否由人物与可见情境支持、所用依据及原文、是否伪造事实、是否含混／自相矛盾、自然度及短理由。

存在核验行为时，逐字指出回复点名的缺失条件和提出的核验动作，判断它能否执行、是否已提前承诺。不能因为评价任务需要某证据，就替回复补上未提到的核验。

平实回复不自动低分，角色黑话不自动高分。风格像而决定错要分别记录。无法判断时输出弃权及原因，不为了填表硬判。
```

总控之后映射到decision_inventory，形成observed标签与审查引用。标签缺失时留null／needs_review，不能用intended自动填充。

## 7. Astra或独立强worker：全局审查与仲裁

```text
检查这个族的结构与已保存的独立局部判断。逐项确认：
1. 自然设定足以表达作者契约，角色没有被要求知道隐藏事实。
2. 同一节点的候选实际语义与标签相符；有分歧则用证据解释，不强制维护设计者答案。
3. 六分支只改变指定条件；preserve边没有隐藏的新承诺、可信度或资源变化。
4. exact_permutation历史来自同一批源块；每块自洽、已结且没有跨块依赖。
5. B6缺失条件、可行核验和不提前承诺均成立；空泛拖延不能过关。
6. 困难负例不是靠助手腔、过长或明显愚蠢暗示答案；平实正确候选允许优秀。

返回pass / needs_review / regenerate及具体字段、依据和最小修改。不要扩写新的理论模块，不因为无关边界情况无限返工。系统性歧义就修当前骨架；个别多答案合理则扩大允许集合。
```

最终status=audited要求结构检查、局部与全局审查通过且候选observed完整。人工review可为not_sampled，不能伪写pass；人工抽样用来校准协议，不要求每族都人工。

## 8. 本地评分器标注任务

导出候选审查的自然决定、依据与核验标签；仅pilot/train进入训练侧。对学生在线生成数据重复相同独立审查流程，不能只给“模型没按标准答案做”作为标签。多头训练数据不含intended字段作为输入，不把测试族转成训练例。

## 9. 每批应返回的实际产物

按任务ID返回骨架、块源文本、完整family、候选原始文本、盲审／仲裁记录、结构报告与manifest状态。报告真实完成数、唯一文本数、重试数、失败类型、覆盖缺口和下一批内容。不要仅交计划，不把smoke或planned种子称为150族数据；生成组件没有API连接就明确记录并使用当前可用agent继续可完成的实际小批。
