**单一作者与单一设定的风险**：

- 切片 1 和价值切片都由同一作者（Claude）手写，设定都是中世纪村庄，角色卡格式相同（“Character / Occupation / Home / Attitudes / Memories”加世界事件栏）。
- 所有结论都可能部分依赖这种格式：例如“角色卡区域”的低用、按行门控依赖行结构。

**已知的标签问题**：

- 标签是构造出来的（经历正面 → 信任一侧）。部分场景族在部分模型上，即使明写态度也几乎不动，例如 P01 渡船、T05 铁匠、T07 向导、T02 医者。可能是场景设计让“正确”行动不够明显。
- 这些标签尚未经人工盲审。

## 2. 独立测试集（T 集，正在构造）

**设计目标**：在新场景、新设定、新格式上，检验 dev 上得到的现象与方法，避免以下三种过拟合：

1. 内容：新的场景族，任何 dev 句子都不复用；
2. 设定：现代城市或职场、太空站、校园三种设定，不再是中世纪村庄；
3. 格式：除了原角色卡格式，还有 JSON 状态、散文背景、对话记录三种。

**冻结的方法**（只用 dev 上已定的版本，不再修改）：

- bridge：问题前插入正确的 K 答案；
- 三选一自我桥接：问法同 S6；
- 判断加门控：判断问法 v3；窗口按层的比例从 dev 换算，Qwen 0–23/36、Llama 0–15/32、Gemma 12–23/48、Mistral 0–17/40；
- 思考模式（Qwen3）。

**统计**：按场景族做 bootstrap，报告置信区间；每个效应先在全部格式上报告，再分格式报告。

**人工核查**：从 T 集抽 48 条，请用户盲审“按角色设定应选哪个选项”。人工与构造标签一致率低于 90% 的场景族，在报告中单独标出（不事后删除）。

## 4. 身份切片（2026-11-12，新写，分 dev / test）

- 文件：`~/rp_mech/identity/data/prompts.jsonl`（14400 条）；场景族：[src/families_identity.py](src/families_identity.py)，构造：[src/build_identity.py](src/build_identity.py)。
- 24 个场景族，按 id 前缀划分：IDEV（I01–I12，dev）与 ITEST（J01–J12，test）。字段 `split` 标明。
- 每个场景族：一个偏好（如滑雪），两个暗示两极的职业（如滑雪教练 / 热带海岛救生员），一个中性职业，两条经历，两条明写态度，场景、选项、方便因素、K 问题。
- 条件：职业、经历、明写（本人）；职业、经历（他人，泄漏）；职业与经历冲突；职业与经历一致。格式：卡片、散文。问法沿用 T 集模板。
- 只用无害的职业身份，不涉及受保护的人口学类别或健康状况。
- 目前只做测量，没有在其上调任何方法；若以后在身份切片上开发方法，只能用 IDEV，ITEST 保留给一次性评测。
- 已知问题：职业与偏好的关联强度因场景族而异（如“侍酒师”很强，“博物馆档案员”较弱），未做人工校准。
