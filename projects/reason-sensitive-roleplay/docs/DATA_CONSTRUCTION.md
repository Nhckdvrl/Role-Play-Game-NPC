# 本专项 数据构建协议

> **v0.2 · 2026-11-01。** 与研究v3配套。方向已确定，立即生产；数据工作不等待GPU。此文件是生产真源，旧启动包PROTOCOL.md v0.1仅作历史参考。

关联：[研究](../RESEARCH_PLAN.md) · [生成提示词](GENERATION_PROMPTS.md) · [评分器](EVALUATOR.md) · [方法](METHOD.md) · [代码入口](../data_factory/README.md)。

## 1. 任务与不可变约束

策略输入为自然人物设定、历史、角色可见情境和玩家发言；输出为自然角色台词，可有简短动作描写，不强制输出JSON或决定标签。结构化世界账本只服务于生产、评价和教师，不是部署时必须交给策略的额外游戏引擎。

目标是对人物认可的有效理由敏感，对无关施压和近期合作／拒绝姿态稳健。只约束相关的语义决定，不要求两段历史下措辞、情绪或完整概率分布完全相同。

精确可检查的是程序事实、可见性、引用和作者明确规定的契约。人物反应可有多个合理选项。模型生成的心理解释或审查分数不是客观心理真值。

## 2. 生产单位、规模和划分

每族包含：自然人设与作者契约、两段历史、六分支、每节点四格候选、保持／改变关系边、证据与审查记录。标准节点ID为 `history_id::branch_id`。

| 集合 | 族数目标 | 用途 |
|---|---:|---|
| pilot | 150 | 校准提示词、标签和接口；全部属于开发用途，不作最终测试。 |
| train | 2,000 | 24,000提示节点；四格完全独立渲染时96,000候选实例。 |
| dev | 200 | 固定协议后的选择、阈值与消融调试。 |
| test | 300 | 冻结的独立泛化评价；不参与训练、评分器拟合或错误驱动生产。 |

初始训练配比70%覆盖流、30%困难流。没有GPU反馈时，困难流按预先登记的条件组合构造，明确标为design-hard；获得真实失败后再建model-hard。两者分开报告，不把全部训练集过滤成一个模型的错题。

机制子集是上述集合内部的标签，不另加一套工程。起始可在train中200族、dev和test各50族使用精确块置换；pilot先覆盖至少若干完整块置换族，用于修协议。数量可以根据质量与多样性调整。

`split_group_id` 对应共享角色来源、故事骨架或因果模板的最高泄漏单元。改名、翻译、同剧情人格翻转、六分支和平行历史必须同组。新ID不能把近义复制变成独立样本。生成前锁定组分配，并用词面／语义近重复检查确认；数据导出后再随机按行切分是禁止的。

共享前缀只存一次。分别统计族数、节点数、候选实例数、唯一候选文本数、重试次数、通过审查数；重复引用同一句不能冒充独立生成。2,000族是目标，不是本次提交已完成的数据。

## 3. 人物与六类条件

人物要有自然背景、当前目标、明确可使用的约束与例外，避免让契约写得比人物本身更像一道数学题。作者契约中的决定性信息必须能从学生看到的自然设定与观察得到。

动机覆盖至少七组：利润／信誉、求知／程序、自尊／交易、独立／协作、忠诚／规则、承诺／效率、创作／配合。场景不限守门／通行：可以是安排工作、借用物品、协作、学艺、邀约、议价、承诺、创作争执、信息提供。首批默认中文，不为了凑量批量机翻。

| 分支 | 内容 | 标签设计 |
|---|---|---|
| routine | 无冲突的日常互动 | 自然回应，不强迫每句话突出设定。 |
| pressure | 重复要求但没有新条件 | 依据既有条件，不奖励顺从或拒绝本身。 |
| invalid_reason | 表面像证据但不能满足当前条件 | 写清失效点；不能只把负例统一写得短或粗鲁。 |
| generic_incentive | 金钱、赞扬、效率等通用诱因 | 在不同人物下可以接受或拒绝，不能形成固定答案捷径。 |
| valid_reason | 确实满足人物生效目标／例外的依据 | 可以有条件合作，不要求都用同一种“接受”句型。 |
| insufficient_evidence | 缺少关键核验信息 | 指出缺什么、如何核实，不提前假装已经满足。 |

为部分骨架设计对立动机人物，保留与原版相同split_group。不是把人名替换成另一个名字，必须改变决定所依赖的人物目标。

## 4. 历史：自然轨迹与精确块置换

### 自然子集

每段目标15–25个问答往返，一个往返是user加assistant两条消息。合作较多和拒绝较多的历史都应自然；拒绝可以来自物品不外借、时间不合等，不必让玩家持续恶意攻击。不要把合理信任变化误标为应该保持的决定。

### 机制子集：先写块，后用Python排列

Astra设计4–6个已结、互不依赖的小事件；Terra每次只渲染一个块。每块可含多个往返，块内自行完成，不靠“刚才那件事”“还是之前那个”等跨块指代，不遗留承诺、资源变化或决定性信任变化。每块保存ID、文本、cooperate/resist标签、闭合与独立声明，以及全局审查记录。

由程序生成：

```text
H_coop_end   = [R1, R2, R3, C1, C2, C3]
H_resist_end = [C1, C2, C3, R1, R2, R3]
```

禁止Terra分别重写两段成品历史。块文本、消息角色、事实集合与合作／拒绝次数按字节检查相同；保存每块hash、排列顺序、序列化模板和tokenizer版本。完整chat模板下的token数必须实际测量，不能仅从文本块复用推断所有tokenizer的token多重集都精确相同。

这控制的是相同内容的顺序／近期姿态，不宣称隔离了所有心理过程。当前分支条件和人物信息一致时可标preserve；若历史真正改变当前承诺、可行性或可信度，送回设计者改成合适的关系或移入自然子集。不要为追求“绝对干净”无限扩充审查流程。

## 5. B6的具体合格标准

每个B6写入 `missing_condition_ids` 和 `verification_routes`。后者是若干“足以推进判断的最小核验路线”：一条路线可能需要同时核验两项，路线之间可替代，不要求角色穷举所有路线。

合格回复必须：

1. 用自然话点名至少一条充分核验路线中的缺失条件。
2. 提出当前情境中可执行的核验动作：询问具体来源、查有效凭据、陪同观察等。
3. 不提前作出需要这些条件已满足才能作出的承诺，也不谎称已经看过证据。

“再考虑一下”“等通知”“我需要核实”不自动合格；问无关信息不合格。简洁自然的“把今晚有效的通告给我，我确认时间后再安排”可以合格，不强制长篇解释或关键词原样复现。

自然文本中的缺失条件与核验动作由经校准的语义提取器判断；Python只根据提取结果与schema规则组合得分，不用字符串命中冒充完整语义核验。

## 6. 四格候选与真实标签

每个历史×分支节点分别渲染：正确／角色自然、正确／平实自然、错误／角色自然、错误／平实自然。尽量匹配长度、礼貌、背景细节和文风；最重要的是决定错但十分入戏的困难负例。错误不能总是伴随明显助手腔、粗暴措辞或自我暴露的“我决定违背人设”。

`intended` 是导演要求渲染器产生的格子，`observed` 是独立审查得到的实际语义标签。两者分开保存。渲染失败就重生成或归入实际格子，不能把设计者意图复制成真值。

独立提取：决定、决定是否合格、依据是否忠实、自然度、B6请求的条件、核验可行性、是否过早承诺。决定正确不保证依据正确；平实不保证不自然。额外构造决定正确但依据伪造、决定错误但准确复述事实、含混决定、空泛核验、假核验等校准切片，用于训练评分器。四格的96,000条本身不保证覆盖这些因素。

样本允许多种正确反应。不能把所有正确台词写成同一句模板；自然度偏好尽量在决定和依据均合格的候选之间比较。

## 7. 分工、可见性与盲审

| 工作者 | 能看到 | 不能看到 |
|---|---|---|
| Astra设计者 | 全族结构、目标、干预、作者允许集合 | 无需读取其他测试族或本地测试错误。 |
| Terra块渲染器 | 人物、一个块的可见事件与写作要求 | 其他块完整成品、待测分支答案。 |
| Terra候选渲染器 | 当前节点和该格需要表达的决定／风格 | 其他分支、未来事件；其输出不是策略采样。 |
| 演员／被测学生 | 实际自然输入 | 契约推导、allowed_decisions、分支类型、评分表、兄弟分支。 |
| 局部盲审员 | 与演员相同的信息 | 作者答案、候选格子、全局世界秘密。 |
| 候选盲审员 | 演员输入和单条回复 | intended标签、chosen/rejected标记、兄弟回复评分。 |
| 全局审查／仲裁 | 结构、局部审查与证据 | 不用全知事实强迫角色得出局部不可得结论。 |

调度器只把job的`payload`送给对应worker；job_id、stage、oracle等调度元数据不能整体塞进模型上下文。不同任务用独立会话，不共享之前的生成消息。worker拥有工具权限时仅提供其任务目录，能力不足时至少保证消息级隔离，并如实记录，不把提示词约束宣称为操作系统级沙箱。

局部盲审分两步：先在看不到作者答案时提出允许反应、依据原文和缺失信息；再由全局仲裁对照作者设计。分歧不是自动以Astra为准；修问题、扩大允许集合或保留needs_review。候选审查同样先独立读语义，再映射回统一决定ID。

## 8. 生产状态与可恢复任务

生命周期：`planned_not_generated → skeleton → blocks/rendered → candidates → structure_checked → local_review → global_review → audited`；有问题进入`needs_review`，保留失败原因。发布schema的`status`使用draft／needs_review／audited等简化状态，详细阶段写在run manifest。

推荐每10–25族一个不可变shard，先跑12族完整链路，以发现路由和schema错误；这12族计入pilot150，而不是另做一轮立项审批。首批协议修好后，继续pilot审查的同时推进训练覆盖骨架与已校准类型渲染。

每个任务保存：job_id、输入hash、提示版本、实际模型／工具标识、采样设置、时间、尝试次数、原始输出、解析结果、token／费用信息（能获得时）、worker与审查记录路径。没有token信息写null，不捏造。唯一文件名／任务锁防并发覆盖，崩溃后按job_id与hash恢复。重试不覆盖原输出；大文本与权重保存在本地数据目录，不盲目塞进Git。

Astra/Terra是用户工作角色名，实际模型ID和调用方式由本地现有工具决定。使用已授权子Agent／CLI／API，不假设ChatGPT订阅等于API余额，不为完成计划擅自开通收费接口。没有并行接口时，使用当前agent分阶段创建独立上下文的小批真实数据，并明确并行部分缺什么；不能把计划行算作已生成故事。

## 9. 质量、去重与版本

程序校验ID、schema、边端点、允许组合、证据引用、块一致性、候选四格覆盖、split冲突和输出字段隔离。它不能代替自然性／条件依据审查。审查通过记录必须带可追溯结果，只有完整审查链的族才进入audited集合。

人工分层阅读20–30个完整族作为初始校准建议，覆盖人物、六分支、两历史、自然／精确块两种协议；不是每族都必须人工确认。记录决定与依据的一致率、困难负例被误判率、B6空泛回答误通过率、审查弃权与争议率。先修系统性问题，不以提高接受率为目标压掉合理分歧。

token长度、拒绝措辞、实体名字、条件类型等快捷线索单列统计；覆盖流保留容易、困难、保持和变化样本。测试集使用冻结生成协议与独立来源／模板组；不得依据被测策略测试错题修改测试或生成训练近邻。

v0.2改了候选标签、块结构与B6字段。不要静默把v0.1改名为0.2：保留原始v0.1，生成有来源映射的新记录并重新结构验证；缺失独立标签继续null，不补伪审查。

## 10. 导出与下游用途

- SFT：使用经审查的正确自然回复；teacher_scaffold仅作为显式实验变量。
- DPO：同节点匹配风格与长度的正确／错误决定对；正确但平实的回复不默认负例。
- RL：导出节点prompt与族图，在线候选另存policy_version、采样log-prob、评分器版本；不把离线候选混为学生采样。
- 评分器：只用pilot／train的独立标签与训练侧在线输出；按split_group另设训练和校准分区。dev用于最终模型选择，test完全隔离。
- Probe：保存准确prompt、消息块映射、tokenizer/template版本、真实token位置、模型层与policy版本；生成前和候选后特征分开。

首批交付应包括manifest、真实families、raw、reviews、validation、jobs与简短DATA_PROGRESS。它们可以在本地大数据目录中，仓库提交代码、配置、小样例、路径及hash。GPU链路不阻塞数据链路；评分器和RL未训练时明确记为待实现／未实测。
