## 二、首选方案 C：阶段忠实的角色扮演（Stage-Faithful Role-Play）

### 2.1 原 C 的问题（用户第 4 轮指出）

第 3 轮的 C 是“时间被压缩的角色表征”，核心贡献押在 H1（早期阶段会系统性地偏向终局）这个**未证实**的现象上。如果 H1 不成立，就没有论文；而且它是纯分析，缺少方法。**这是在赌。**

### 2.2 改造原则

1. **问题本身必须已经确立**，不依赖新假说；
2. **方法的每个组件都要有独立的先验证据**；
3. 尚未证实的现象（终局吸引子、事实与状态的分离）只作为解释性的诊断模块：成立则加强论文，不成立也不影响论文成立；
4. 训练标签和主要评测尽量来自**结构化信号**，不来自未验证的裁判。

### 2.4 尚未证实、不作为前提的假设

- **U1 默认吸引子**：不给阶段时，模型偏好某个固定阶段（终局或开局的典型状态）；给定阶段后出错，也会被拉向这个阶段。
- **U2 事实与状态分离**：事实层面守住了边界（不剧透），态度和状态层面仍然越界。
- **U3**：仅凭“到目前为止的剧情”，足以推断出当前阶段。

### 2.5 问题定义

- **输入**：可能是“时间压缩”的人设卡（E7：CoSER 这类按书构建的人设卡里带着结局），到时点 t 为止的剧情（可以部署拿到的信息），以及当前场景或对方发言。
- **阶段错位的两个来源**：
  - (a) **上下文来源**：人设卡里写着未来。**“存在”已确立（E7），“有害”未测**（第 5 轮修正）；
  - (b) **参数来源**：预训练里的原著印象，部分已确立（E3），方向性是假设（U1）。

  方法要同时处理两者。**第 5 轮的诚实结论：(a) 是否有害，是改造后 C 剩下的唯一承重点，见 2.12。**
- **输出**：角色化的回应（行动、想法、台词），应当符合 t 所在阶段的态度、关系与知识。
- **目标**：在**不依赖离线弧线**的条件下，缩小“部署可得信息”与“特权阶段信息（Arc）”之间的差距（E1、E6 表明这个差距存在）；同时守住事实层面的时间边界，并且不损害正当知识（例如“过去在场”的事实）。

### 2.6 方法（各组件及其先验）

1. **训练无关：阶段复述（Stage-Recall）**。作答前先用简短、受约束的一句话复述“我现在在哪里”：最近发生了什么、我此刻对关键人物的态度、哪些事还没发生，然后再作答。
   - 先验：Self-Recall（E4）；ArcHint 说明显式点出阶段就是收益的大头（E2）。
   - 注意：它必须是受约束的复述，而不是开放式 CoT，后者已被证明有害（E4）。
2. **训练：阶段可接受性批判微调（TCFT 的形式）**。训练模型判断“在阶段 p 的上下文下，这条回答是否符合当前阶段”，并给出理由；测试时直接作答。
   - 先验：TCFT 在时间泄露上的大幅收益，以及它的消融结果（批判的内容必须针对“时间可接受性”，换成一般事实批判就无效）。
   - **关键的数据优势**：ArcANE 对每个探针都给了每个阶段的参考回答，所以“阶段 q 的回答放在阶段 p 的上下文里是否可接受”的标签是**结构性**的（q=p 可接受，q≠p 不可接受），**不需要 LLM 教师裁判**。这正好落实了我们的头号教训。理由文本可以由阶段描述模板生成，少量用于验证。
3. **作为对照或变体：对比解码**。负例上下文取“只有人设、没有阶段”的版本，形式与 FACD 相同（E5）。它的新颖性低，不作为贡献，只作为强基线和机制解释（对比项正是 U1 所说的“默认吸引子”）。

### 2.7 数据

- ArcANE 的训练集和评测集（CC-BY）：训练集用来构造批判数据；评测用经验证的 205 条弧线、1754 个探针（公开版不含哈利波特），以及作者划出的冷门书。
- 事实层面：TimeChara（“未来”与“过去在场”配对）、CHARM 风格的识别与遵守题，用来测事实边界和过度戒备。

### 2.8 评测（落实“先验证测量”）

1. **不依赖裁判：似然阶段归因**。在阶段 p 的上下文下，用教师强制计算对各阶段参考回答的对数似然，减去基线上下文下的值，得到阶段辨别准确率和错误方向。
2. **生成匹配**：判断回答最接近哪个阶段的参考。裁判用推理模式，先用约 100 条人工盲标验证，一致率达不到标准就不用。
3. **独立于 ArcANE 流水线的信号**（缓解循环）：情境内探针对应的原文段落里，角色实际做了什么；少量人工标注；TimeChara 的事实题。
4. **回归检查**：“过去在场”类的正确率（防过度戒备）；通用角色质量（经验证的裁判）；APC 设定事实使用。
5. **基线**：Vanilla、摘要、RAG、Arc（特权信息，作为上限参照）、ArcHint、Self-Recall 式提示、FACD 式对比解码、**ArcANE-8B-DPO（已发布权重）**、对参考回答做 SFT。

### 2.9 诊断模块（U1、U2）：Gemini 三层似然设计的评估与修正

**设计**：匿名中性上下文 → 只给角色身份（不给阶段）→ 角色加指定阶段。以第二层的峰值阶段 q* 作为“默认吸引子”，检验第三层出错时是否偏向 q*。它能避免“偏终局”和“偏开局”的角色正负抵消，思路正确。

**需要修正的五个漏洞**：
1. **探针本身不是“无阶段”的**：情境内探针是原文段落，带有章节线索，第二层并不真正无阶段。应只用世界内和世界外探针，它们是虚构情境。
2. **匿名化不彻底**：场景文本里有人名和地名。除了匿名上下文，还应加一个“错误角色”上下文（换成同类型的其他角色，类似 ArcANE 的 MixedArc）作为第二基线。
3. **q* 的估计噪声大**：平均每条弧线只有约 3.5 个阶段，单个探针上的似然差噪声很大。应按弧线跨探针聚合，做拆半信度检验，只用 q* 可靠的弧线。
4. **相邻混淆**：q* 与 p 相邻时，“被吸引子拉走”和“相邻阶段混淆”无法区分。只能在阶段数至少为 3、且 p 与 q* 不相邻的样本上检验。
5. **文风混杂贯穿各层**：如果终局阶段的参考回答整体上更“像这个角色的文风”，第二、三层都会偏好它，但这与预训练记忆无关。对照办法：比较知名书和冷门书，以“模型在故事外知道该角色的弧线”为条件分析，并检查似然归因与生成匹配是否一致。

U2（事实与状态分离）可以通过同时测 TimeChara 式事实题和 ArcANE 式态度题来报告，不需要额外的数据构造。

### 2.11 剩余风险与新颖性

- **循环**：训练标签和评测参考答案都来自 ArcANE 流水线，方法可能只是学会了 ArcANE 对人物的那一种解读。缓解办法见 2.8 第 3 条，但无法彻底消除。
- **新颖性**：审稿人可能认为是“Self-Recall 加 TCFT 搬到角色阶段上”。区别在于：
  - 目标是**潜在的状态**而不是日期，需要从剧情中推断；
  - 标签是结构性的，不来自裁判；
  - 明确对比了事实层与状态层，并在不依赖裁判的测量上评测。

  够不够，需要旁观者判断。
- **参考答案噪声**：22% 的相邻阶段对区分度弱，人物弧线的人工一致性中等（AC1 0.70）。
- **知名度跨度有限**：公开版去掉了哈利波特。
- **与游戏 NPC 的距离**：探针是单轮的；通过“剧情阶段 / 任务阶段”来类比游戏。

### 2.12 第 5 轮核查后的修订（2026-11-02）

**(1) 承重点：时间被压缩的上下文是否真的伤害早期阶段？**

- 已确立的只是“存在”（E7）；“有害”没有任何直接测量。ArcANE 没在这种条件下评测过（E8），而它的训练数据恰好一直带着整条弧线的总结（E9），这至少说明“上下文里有未来信息”不是一个被避免掉的稀有情形。
- 如果没有可测的伤害，“从全书人设卡中解耦当前阶段”这条主线就不成立。C 会退化为“ArcANE 加一个只用部署信息的方法”，新颖性明显下降。这是现在必须如实承认的风险，不能当作已确立的前提。
- 这个问题可以**不经裁判、不用新写文本**来测：ArcANE 的弧线 JSON 本身就能构造“截断到当前阶段”与“展示全部阶段（时间压缩）”两种上下文，用各阶段参考回答的似然比较即可（完整弧线可从训练数据中 pole_end 存在的样本恢复，10 本书、308 条带方向标注的弧线）。这里只记录“它可测、测法是结构性的”，不在讨论阶段展开实验。

**(2) Gemini 的“三向时态剥离（<p / =p / >p）”**

- 作为**分析维度**有价值：ArcANE 论文没有报告错误方向。
- 作为**方法差异**不成立：ArcANE 的 DPO 已经在两个方向上各约一半地用其他阶段当负例（E9）。在批判微调里显式标出“过去/未来”，相对 ArcANE-DPO 的增量很小。
- “必然能画出清晰的不对称”是在赌，而且有结构性混杂：
  - 阶段 p 是第一阶段时，错误只可能偏向未来；是最后阶段时，只可能偏向过去。直接比较“早期抢跑率”和“后期滞留率”，会把位置约束误读成规律。
  - 66% 的弧线只有 3 个阶段（2 个阶段 9%，4 个 23%，5 个 2%），能同时犯两种错误的只有中间那个阶段，而它的两侧都是相邻阶段，又回到相邻混淆问题。
  - 约 12% 的弧线标注为 flat 或 ambivalent（另有 positive 68%、negative 13%、disillusionment 7%），这类弧线的“过去/未来方向”在心理维度上没有清楚定义。
  - 合理的做法：只在内部阶段上比较方向，并以“随机错误下的方向分布”为基线。

**(3) Gemini 的“识别 vs 执行”两步诊断（回应 U3）**：采纳为诊断设计，但它不是“稳赚不赔”：
- 还有第三种结果：只给剧情，模型就能识别对、也演对。那说明部署场景下问题不大，论文会变弱。
- 识别题若以选择题形式给出阶段名，本身就提供了类似 ArcHint 的信息，与执行题的输入条件不同，两者比较时要说明。

**(4) Gemini 的“用 CoSER 做独立外部锚点”**：按原说法不可行。
- CoSER 测试场景集中在每本书末尾（E7），没有“早期场景配全书人设卡”的样本。
- 参考回复中的内心想法 `[...]` 是 LLM 生成的，台词和动作是 LLM 从原文抽取的，不等于“100% 原著”。
- CoSER 没有阶段标注。
- 可行的变体：用完整 CoSER 数据（771 本书）中**训练部分**的早期情节，以原文台词的似然作为不依赖裁判的信号。但 CoSER 系列模型训练过这些情节，只能用于非 CoSER 模型。

**(5) Gemini 的“游戏和平台普遍只塞一张总设定卡”**：与事实不符。
- Convai 的 Narrative Design 是“剧情段落图”，每段有自己的 objective，由触发器推进；
- Inworld 有 mutations（运行时改人设字段和场景描述）、关系状态（信任、熟悉度等数值）、知识过滤；
- SillyTavern 用关键词触发的 World Info / lorebook 按需注入设定。
- 这反而**削弱**了 C 的游戏动机：游戏引擎通常**知道**当前处在哪个剧情阶段，可以显式告诉模型，而 E2（ArcHint 接近完整 Arc）表明显式提示就能拿到大部分收益。游戏场景下仍然开放的问题，是“静态基础人设里的后期内容”与“当前阶段 objective”之间的冲突，以及阶段状态的编写成本。“只能从剧情推断阶段”（U3）更贴近开放式长线扮演和连载类应用，而不是有状态机的游戏。

**(6) C 与 2b 的取舍**：仍选 C，但理由需要修正：角色阶段状态这条线**不是** CHARM、TCFT 没碰过的空白赛道，而是 ArcANE 的赛道（EMNLP 2026 主会、已发布数据和模型）。C 的增量只能来自“部署可得信息 + 时间被压缩的输入”这一 ArcANE 未覆盖的条件，而这个条件是否造成可测的伤害，正是 (1) 的承重点。


### 2.13 第 6 轮：为什么 C 不再推荐立项（2026-11-02）

**接受 Gemini 的警钟二（工程过滤）**：如果早期阶段受损只是因为人设卡里写着结局（来源 a），最直接的解法是在输入端按当前章节清洗人设卡（HER 的按场景人设卡、ArcANE 评测时的截断都是这样做的），而不是训练演员模型忽略它。第 1 轮我们正是用同一条理由放弃了 2a。第 5 轮我把 (a) 定为“唯一承重点”时没有用这条标准检验自己，这是我的疏漏。

**警钟三（训练空间只有 1–3 分）的数字有误，但指向的问题更致命**：
- 2.2–8.4 分是“Arc 比**最好的**非 Arc 模式高多少”。Vanilla 到 Arc 的差距是 +5.9 到 +13.9 分：DeepSeek-V4-Flash 52.9→59.7，Pro 52.4→62.4，Qwen3-8B 37.2→43.1，Qwen3-32B 43.7→50.1，ArcANE-8B-DPO 43.0→56.9，ArcANE-32B-DPO 49.9→60.4。ArcHint 接近 Arc 只在 DeepSeek-V4-Flash 和 Qwen3-32B 上成立（约 120 个探针）；在 ArcANE-32B-DPO 上，ArcHint 只拿回约一半收益。
- 更致命的是：**ArcHint 只是“当前阶段的编号和名称”，而在 ArcANE 里，阶段完全由章节号和弧线 JSON 中的 chapter_range 决定，查表就能得到**。所以：
  - 有弧线时，阶段提示几乎零成本可得，ArcHint 本身就是可部署的；
  - 没有弧线时，“阶段”没有定义，“阶段忠实”只能借 ArcANE 的参考答案在离线评测中定义；
  - 游戏引擎通常知道剧情阶段（第 5 轮）。

  因此，“不依赖离线弧线、只用部署信息”这个问题设定，在主要场景里都站不住。

**警钟一（ArcANE-8B-DPO 可能已经“免疫”）**：这是推测，没有数据支持。ArcANE-8B-DPO 高度依赖 Arc 上下文（Vanilla 43.0，Arc 56.9），它在时间压缩上下文下的表现未知。由于 (a) 已经被工程过滤这条理由排除，这一点不再影响结论。

**门槛测试不再必要**：Gemini 提的三个数字中，(1) 即使测出伤害，仍会被“清洗输入”驳回；(3) 的前提是 (a) 成立；只有 (2)（干净上下文下参数先验造成的阶段错误）仍有意义。但 (2) 是 U1 式的现象测量，属于纯分析；而且“在干净 Arc 上下文下压住参数先验”正是 ArcANE-DPO 的训练设定。测出来也无法支撑一个新的方法论文。

**结论**：C 的研究问题有意思，但找不到同时满足“问题已确立、有新方法空间、部署场景成立”的版本。不立项，设计过程保留在本文件中备查。
